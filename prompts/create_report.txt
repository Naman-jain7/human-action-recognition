### 1. Ensemble or Single Model?
It is implemented as a **2-stream ensemble**. 
*   The notebook defines a core architecture (`CTR_GCN_Network`) and trains it twice: once on the **Joint Stream** (raw coordinates) and once on the **Bone Stream** (vector differences between joints).
*   The final prediction is achieved through **Late Fusion**, where the logits (output scores) from both streams are summed with a 1:1 weighting to produce the final result.

### 2. Type of Model
It is a **Graph Convolutional Network (GCN)**. Specifically, it uses a **Channel-wise Topology Refinement** mechanism. Unlike traditional GCNs that use a fixed or globally learned adjacency matrix, CTR-GCN learns different topologies for different channels, allowing it to capture more nuanced relationships between joints.

### 3. Architecture Layers & Dimensions
The model consists of a normalization layer followed by three main stages of GCN and TCN (Temporal Convolutional Network) blocks:

| Layer | Type | Input Dimension | Output Dimension | Key Detail |
| :--- | :--- | :--- | :--- | :--- |
| **Data BN** | `BatchNorm1d` | `(C * V)` | `(C * V)` | Normalizes skeleton data per joint. |
| **GCN Block 1** | `AdaptiveGCN` | `in_channels` (2 or 3) | 64 | Learns adaptive joint connectivity. |
| **TCN Block 1** | `MultiScaleTCN`| 64 | 64 | Captures temporal patterns. |
| **GCN Block 2** | `AdaptiveGCN` | 64 | 128 | Increases feature depth. |
| **TCN Block 2** | `MultiScaleTCN`| 128 | 128 | Uses `stride=2` for temporal pooling. |
| **GCN Block 3** | `AdaptiveGCN` | 128 | 256 | High-level spatial features. |
| **TCN Block 3** | `MultiScaleTCN`| 256 | 256 | Uses `stride=2` for further pooling. |
| **Global Pool** | `Mean` | `(256, T, V)` | 256 | Averages across Time and Joints. |
| **FC Layer** | `Linear` | 256 | 60 | Maps to 60 action classes (NTU-60). |

*   **Input Shape**: `(Batch, Channels, Time, Joints, Persons)` $\rightarrow$ `(N, 3, 64, 17, 2)`.
*   **Joints**: 17 (COCO skeleton format used with HRNet).

### 4. Activation Function
*   **ReLU** (`nn.ReLU`) is used throughout the model, specifically after each BatchNorm layer in both the `AdaptiveGCNBlock` and the `MultiScaleTCN` modules.

### 5. Optimizer Algorithm
*   **Algorithm**: `SGD` (Stochastic Gradient Descent).
*   **Momentum**: `0.9`
*   **Weight Decay**: `1e-4`
*   **Nesterov**: `True` (Nesterov Accelerated Gradient).
*   **Scheduler**: Typically uses `CosineAnnealingLR` to decay the learning rate from an initial `0.1` down to near zero.

### Summary of Key Performance
The notebook shows that this 2-stream CTR-GCN ensemble achieves significantly higher accuracy (reaching **~95.76%**) compared to the single-stream Pose Transformer (which reached **~82-84%**) or individual GCN streams.





Data - The model utilizes the NTU RGB+D (NTU-60) dataset, containing 56,578 skeleton sequences. It follows the Cross-View (X-View) protocol, where samples from cameras 2 and 3 are used for training (37,646 samples) and samples from camera 1 are used for validation/testing (18,932 samples).
Preprocessing - Data undergoes Uniform Temporal Sampling to resize all sequences to 64 frames. Skeletons are centralized by subtracting the coordinates of the body center to remove translation bias. During training, Spatial Jittering (Gaussian noise with $\sigma=0.01$) is applied for augmentation. Finally, the workflow extracts Bone features (vector differences between joints) to be used as a second stream for the ensemble.
Training - Each stream (Joint and Bone) is trained for 60 epochs. The process uses Stochastic Gradient Descent (SGD) with Nesterov momentum and a Cosine Annealing learning rate scheduler. A validation strategy is employed where the model is evaluated after each epoch, and the best-performing weights are saved based on validation accuracy.
Testing - Evaluation is performed on the unseen validation set following the X-View protocol. The final testing methodology involves a 2-Stream Late Fusion approach, where the output logits from the Joint-trained model and the Bone-trained model are summed (1:1 weight) to compute the final ensemble prediction.
Evaluation - Performance is analyzed using Top-1 Accuracy, Classification Reports (Precision, Recall, and F1-Score for each of the 60 classes), and Normalized Confusion Matrices to identify specific action pairs that the model frequently confuses.
